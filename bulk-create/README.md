# Redmine チケット一括作成ツール(作成・更新)

CSVまたはExcelに書いたチケットを、親子孫の階層ごと、Redmineに一括で作成・更新します。

- 1つのファイルで、ストーリー → 作業区分 → タスクをまとめて作成できる
- **同じ書式で既存のチケットも更新できる**(行IDに `#453` と書くだけ。作成と更新を1つのファイルに混ぜられる)
- **指定したチケットとその下の階層を、同じ書式で書き出せる**(書き出す → Excelで直す → 読み込む、で更新できる)
- **CSV**(`.csv`)と**Excel**(`.xlsx`)のどちらでも読み込める
- トラッカー・優先度・担当者などは、画面に表示される名前のまま書ける
- 新しく作るチケットの題名の頭に、親の題名を自動で付ける(例:`Webサイト刷新:デザイン:ワイヤーフレーム作成`)
- 反映前に「試し実行」で、作成予定の一覧・更新の「変更前 → 変更後」・入力の間違いを確認できる

## 1. 準備(最初の1回だけ)

### ファイルを置く

WSL2で、GitHubから取得します。

```bash
git clone https://github.com/sakagami333/redmine-tools.git ~/redmine-tools
cd ~/redmine-tools/bulk-create
```

新しい版を取り込むときは、`cd ~/redmine-tools && git pull` を実行します。

### フォルダの使い分け

```
bulk-create/
├── redmine_bulk_create.py   ツール本体
├── templates/               配布用のひな形(Git で管理する)
│   ├── sample_tickets.xlsx
│   └── sample_tickets.csv
├── work/                    自分の作業用のファイル(Git で管理しない)
│   ├── 2027-1月分.xlsx          ← templates/ からコピーして書いたもの
│   ├── export-64-20261120.xlsx  ← 書き出したもの
│   └── logs/                    ← work/ のファイルを反映したときの記録
└── logs/                    bulk-create/ 直下のファイルを反映したときの記録
```

- **実際のチケットを書いたファイルは、`work/` に置いてください。** このリポジトリは公開しているため、`work/` の中身と、`bulk-create/` 直下の `.xlsx`・`.csv` は、Git に登録しない設定(`.gitignore`)にしてあります。
- **実行の記録**は、入力ファイルの隣の `logs/` に保存されます(`work/` のファイルなら `work/logs/`)。どの階層の `logs/` も、中身は Git に登録しません。
- `templates/` に置いたファイルは Git で管理され、Push すると公開されます。社内の情報を含まない、ひな形だけを置いてください。

### APIキーを保存する

1. Redmineの右上のユーザーメニュー →「個人設定」を開く
2. 右側の「APIアクセスキー」の「表示」を押し、表示されたキーをコピーする
3. WSL2で次を実行する(`キー` の部分を貼り付けたキーに置き換える)

```bash
echo 'キー' > ~/.redmine_api_key
chmod 600 ~/.redmine_api_key
```

あわせて、Redmineの「管理 → 設定 → API」で「RESTによるWebサービスを有効にする」がオンになっていることを確認してください(管理者の操作が必要です)。

## 2. 入力ファイルの書き方

### Excelで書く(おすすめ)

`templates/sample_tickets.xlsx` を `work/` にコピーして使います。

```bash
cd ~/redmine-tools/bulk-create
cp templates/sample_tickets.xlsx work/2027-1月分.xlsx
```


- **「チケット」シート**:1行1チケットで入力します。2〜8行目は入力例なので、書き換えるか削除してください。
- **「使い方」シート**:作成・更新のルールと、各列の書き方をまとめてあります。
- トラッカーと優先度は、セルを選ぶと一覧から選べます(一覧にない名前も、そのまま入力できます)。
- 開始日・期日は、Excelの日付として入力します(`2027/1/31` などと打てば日付になります)。表示形式は何でも構いません。
- 説明は、セル内の改行(`Alt + Enter`)がそのまま使えます。
- ツールは、「チケット」という名前のシートを読みます。なければ先頭のシートを読みます。別のシートを読むときは `--sheet シート名` を付けます。
- 古い形式の `.xls` は読めません。`.xlsx` で保存してください。

### CSVで書く

```csv
行ID,親,トラッカー,題名,担当者,開始日,期日,優先度,ステータス,対象バージョン,説明
S1,,ストーリー,Webサイト刷新,,2027-01-05,2027-03-31,高め,,,
W1,S1,作業区分,デザイン,,2027-01-05,2027-02-10,,,,
T1,W1,タスク,ワイヤーフレーム作成,,2027-01-05,2027-01-20,,,,
```

- 「CSV UTF-8」でも「CSV(コンマ区切り)」(Shift_JIS)でも保存できます。
- 日付は `2027-01-31` または `2027/01/31` と書きます。
- 説明の改行は `\n` と書きます。

### 新規作成と更新のルール

1つのファイルの中で、行ごとに「新規作成」か「更新」かが決まります。決め手は**行ID**だけです。

| 行ID | 意味 |
|---|---|
| `S1`、`W1`、`T1` などの名前 | **新しく作る** |
| `#453` のように「#」+ チケット番号 | **既存のチケット #453 を更新する** |
| `# 4月分の準備` のように、「#」の後が数字だけでない | メモの行(読み飛ばす) |
| `453` のように数字だけ | **エラー**(既存チケットと紛らわしいため使えない) |

空欄と「-」(ハイフン)の意味は、次のとおりです。

| 書き方 | 新しく作る行 | 更新する行 |
|---|---|---|
| 値を書く | その値で作る | その値に変える |
| 空欄 | 既定値(担当者は自分、優先度・ステータスはRedmineの既定) | **変更しない** |
| `-` | なし(担当者に書くと「担当者なし」) | **空にする** |

- `-` で空にできるのは、担当者・開始日・期日・対象バージョン・カテゴリ・予定工数・説明・親です。トラッカー・題名・優先度・ステータスは、Redmineで必須のため空にできません。
- 更新する行の題名は、**書いたとおり**になります(親の題名は自動で付けません)。
- 更新する行の説明は、書くと**説明全体が書き換わります**。
- 更新できるのは、`--project` で指定したプロジェクトのチケットだけです。
- 更新する行も、ほかの行の「親」として指定できます。たとえば、`#453` を更新しつつ、その下に新しいタスクを作れます。

例:#455 のステータスと期日を変え、#454 の担当者を外し、#454 の下に新しいタスクを作る

```csv
行ID,親,トラッカー,題名,担当者,期日,ステータス
#455,,,,,2027-01-30,進行中
#454,,,,-,,
T9,#454,タスク,追加タスク,,2027-01-20,
```

ステータスだけをまとめて変えるなら、列は2つで足ります。

```csv
行ID,ステータス
#455,進行中
#456,終了
```

### 列の一覧(Excel・CSV共通)

| 列 | 必須 | 書き方 |
|---|---|---|
| 行ID | ○ | 新規は `S1` など、更新は `#453`(上のルール参照) |
| 親 | | 親にする行の **行ID**、または既存のチケット `#453`。空欄なら、新規はいちばん上の階層、更新は変更しない |
| トラッカー | 新規は○ | ストーリー / 作業区分 / タスク など、画面の名前のまま |
| 題名 | 新規は○ | 新規は**自分の部分だけ**書く(親の題名と `:` は自動で前に付く)。更新は書いたとおり |
| 担当者 | | プロジェクトのメンバーの表示名、または「自分」 |
| 開始日・期日 | | 日付 |
| 優先度 | | 通常 / 高め など |
| ステータス | | 未着手 / 進行中 など |
| 対象バージョン | | プロジェクトのバージョン名 |
| カテゴリ | | カテゴリ名 |
| 予定工数 | | 時間を数値で(例:`2.5`) |
| 説明 | | 新規で空欄のとき、**タスクだけ**「このタスクのゴール/対応内容まとめ」の雛形が入る |

- 1行目は見出しです。列の並び順は自由で、使わない列は列ごと省いて構いません。
- 見出しは英語(`key, parent, tracker, subject …`)でも書けます。

### 題名の付き方(新しく作る行)

| 入力した題名 | 作成される題名 |
|---|---|
| ストーリー:`Webサイト刷新` | `Webサイト刷新` |
| 作業区分:`デザイン` | `Webサイト刷新:デザイン` |
| タスク:`ワイヤーフレーム作成` | `Webサイト刷新:デザイン:ワイヤーフレーム作成` |

- すでに `親の題名:` から書いている場合は、二重には付けません。
- 親が更新する行(`#453`)の場合は、更新後の題名が使われます。
- 親の題名を付けたくないときは、実行時に `--no-prefix` を付けます。

## 3. 実行する

### 試し実行(何も反映しない)

```bash
cd ~/redmine-tools/bulk-create
python3 redmine_bulk_create.py work/2027-1月分.xlsx --project my-project
```

- `--project` には、プロジェクトの識別子(URLの `/projects/〇〇` の〇〇)を書きます。
- CSVの場合は、ファイル名を `.csv` のものにするだけです。

予定が、階層ごとに字下げして表示されます。更新する行は、変わる項目の「変更前 → 変更後」が表示されます。

```
接続先    : http://localhost:3000
プロジェクト: テスト(test)
予定      : 新規作成 1件 / 更新 2件

[#454] 更新  作業区分  [SCB]2027#1:グランドスケジュール
      担当者: Sakagami Kimi → (なし)
    [#455] 更新  タスク  [SCB]2027#1:グランドスケジュール:試験日
          期日: 2027-01-23 → 2027-01-30
          ステータス: 未着手 → 進行中
    [T9] 新規  タスク  [SCB]2027#1:グランドスケジュール:追加タスク
          担当: Sakagami Kimi / 〜2027-01-20
```

入力に問題があれば、反映前にまとめて表示されるので、直してから再度実行してください。変える項目が何もない更新の行は「(変更なし)」と表示され、Redmineには送りません。

### 本番実行(実際に反映する)

試し実行の内容に問題がなければ、`--apply` を付けて実行します。

```bash
python3 redmine_bulk_create.py work/2027-1月分.xlsx --project my-project --apply
```

`--apply` を付けたときも、まず試し実行と同じ一覧とチェック結果が表示され、次のように確認されます。`y` を入力すると反映が始まり、それ以外(Enter だけなど)なら、何も反映せずに終わります。

```
上の内容(新規作成 1件・更新 2件)を、http://localhost:3000 の「テスト」に反映します。よろしいですか? [y/N]:
```

確認を省略したいとき(決まったファイルを繰り返し反映するときなど)は、`--yes` も付けます。

結果は、画面に表示されるとともに、**実行の記録**として、入力ファイルの隣の `logs/` フォルダに `入力ファイル名-日時.csv` で保存されます(行ID・処理・チケット番号の対応表)。フォルダがなければ自動で作ります。

```
work/
├── export-482-20261120.xlsx        ← 作業用のファイル
└── logs/
    └── export-482-20261120-20261120-224309.csv   ← 22時43分09秒に反映したときの記録
```

- 記録ができるのは、`--apply` で実際に反映したときだけです(試し実行・書き出し・確認で中止したときは作りません)。
- 保存先を変えるときは `--log-dir フォルダ` を付けます。
- `logs/` の中身は、リポジトリに登録しない設定(`.gitignore`)にしてあります。

### 更新が反映されなかった項目の警告

更新のあと、ツールはチケットを読み直して、指定どおりに変わったかを確かめます。変わらなかった項目があると、次のように表示します。

```
  更新: #454  [#454] [SCB]2027#1:グランドスケジュール
    !! 反映されなかった項目: ステータス(ワークフローの制限や、子チケットから自動計算される項目の可能性があります)
```

主な原因は次の2つです。Redmineは、こうした変更をエラーにせず、黙って無視します。

- **ワークフロー**で、そのステータスへの変更が許可されていない(「管理 → ワークフロー」で確認)
- **親チケット**の開始日・期日・優先度などが、子チケットから自動で計算される設定になっている(「管理 → 設定 → チケットトラッキング」の「親チケットの値の算出方法」)

### 接続先とプロジェクトのエラー

| 表示 | 原因 |
|---|---|
| プロジェクト「〇〇」が … に見つかりません | プロジェクトの識別子が違うか、接続先(`--url`)が違う。試験用など別の Redmine に向けていないか確認する |
| 接続を断られました(HTTP 401 / 403) | APIキーが違う、REST API が無効、またはそのプロジェクトを見る権限がない |
| 接続できません | Redmine が動いていない。`docker compose ps` などで確認する |

## 4. 既存のチケットを書き出して直す

既存のチケットを直すときは、**書き出す → Excelで直す → 読み込む**のが手軽です。

### 書き出す

```bash
cd ~/redmine-tools/bulk-create
python3 redmine_bulk_create.py --export 64 --project my-project
```

- #64 と、その下の作業区分・タスクなどが、すべて書き出されます。複数のときは `--export 64,380` のように並べます。
- 書き出し先は、既定で `work/export-64-日付.xlsx` です(どのフォルダで実行しても、ツールと同じ場所の `work/` に保存します)。`--out ファイル名` で変えられます(`.csv` にすればCSVで書き出します)。同じ名前のファイルがあるときは、上書きせずに止まります。
- 終了したチケットを除くときは、`--exclude-closed` を付けます。
- `--project` と違うプロジェクトのチケット(サブプロジェクトなど)は、書き出しません(画面に表示します)。

書き出したファイルは、読み込みと同じ書式です。

- 行IDは `#453`、親は `#64` の形なので、そのまま読み込むと、すべて**更新の行**になります。
- 今の値(題名・担当者・日付・ステータス・説明など)が入っています。
- 親子の順に並び、題名の列は階層の深さに応じて字下げされます(見た目だけで、値は変わりません)。

### 直して読み込む

1. Excelで、変えたいところだけを直します。新しい行(`T9` など)を足せば、子チケットの追加もできます。
2. 試し実行で確認します。

```bash
python3 redmine_bulk_create.py work/export-64-20261120.xlsx --project my-project
```

**直したところだけ**が「変更前 → 変更後」として表示され、触っていない行は「(変更なし)」になります。Excelを通すと変わりやすい改行コードや末尾の空白の違いは、変更として扱いません。

3. 問題がなければ、`--apply` を付けて反映します。

## 5. 途中で失敗したとき

- 反映中にエラーが起きると、**その時点で止まります**。それより前の行は反映済みです。
- 反映済みのものは、実行の記録(`logs/` の `入力ファイル名-日時.csv`)に残っています。
- 続きから行うときは、入力ファイルから反映済みの行を削除し、作成済みの親は `#番号` に書き換えてから、もう一度実行してください。

## 補足

- **書き出してから時間がたったファイルに注意**:ツールは、読み込んだ時点のRedmineの値と、ファイルの値を比べます。書き出したあとに、ほかの人(または画面からの自分)が同じチケットを変えていると、ファイルに残っている**古い値に戻す変更**として表示されます。試し実行で、直した覚えのない「変更前 → 変更後」がないか確認してください。迷ったら、書き出し直してから直すのが確実です。

- 接続先は既定で `http://localhost:3000` です。変えるときは `--url http://…` を付けます。
- Python 3の標準機能だけで動くので、追加のインストールは不要です(Excelの読み込みも含む)。

## コマンドリファレンス

### 書式

```bash
# 読み込み(作成・更新)
python3 redmine_bulk_create.py <ファイル> --project <識別子> [オプション]

# 書き出し
python3 redmine_bulk_create.py --export <番号> --project <識別子> [オプション]
```

### 引数とオプション

| 指定 | 使う場面 | 意味 |
|---|---|---|
| `<ファイル>` | 読み込み | 読み込む CSV(`.csv`)または Excel(`.xlsx`)。書き出しのときは指定しない |
| `--project`, `-p <識別子>` | 両方(必須) | プロジェクトの識別子(URL の `/projects/〇〇` の〇〇) |
| `--url <URL>` | 両方 | Redmine の URL。既定は `http://localhost:3000` |
| `--sheet <シート名>` | 読み込み | Excel の読むシート。既定は「チケット」シート、なければ先頭のシート |
| `--apply` | 読み込み | 実際に反映する。付けなければ試し実行(何も反映しない) |
| `--yes`, `-y` | 読み込み | `--apply` のとき、反映前の確認(`[y/N]`)を省略する |
| `--no-prefix` | 読み込み | 新しく作るチケットの題名の頭に、親の題名を付けない |
| `--log-dir <フォルダ>` | 読み込み | 実行の記録の保存先。既定は、入力ファイルの隣の `logs/` |
| `--export <番号>` | 書き出し | 指定したチケットと、その下の階層をすべて書き出す。`64`・`#64`・`64,380` の形で指定 |
| `--out <ファイル>` | 書き出し | 書き出し先。`.csv` ならCSV、それ以外は Excel。既定は `work/export-番号-日付.xlsx` |
| `--exclude-closed` | 書き出し | 終了したチケットを書き出さない |
| `--help`, `-h` | 両方 | 使い方を表示する |

- `--export` と `<ファイル>`、`--export` と `--apply` は、同時に指定できません。
- 書き出し先に同じ名前のファイルがあるときは、上書きせずに止まります。

### よく使う例

```bash
# 試し実行(作成・更新の予定と、入力の間違いを表示するだけ)
python3 redmine_bulk_create.py work/tickets.xlsx -p my-project

# 反映(予定を表示 → y で確認 → 作成・更新)
python3 redmine_bulk_create.py work/tickets.xlsx -p my-project --apply

# 確認なしで反映
python3 redmine_bulk_create.py work/tickets.xlsx -p my-project --apply --yes

# 試験用など、別の Redmine に向ける
python3 redmine_bulk_create.py work/tickets.xlsx -p my-project --url http://localhost:3001

# 既存のチケット #64 と、その下をすべて書き出す
python3 redmine_bulk_create.py --export 64 -p my-project

# 複数のチケットを、終了したものを除いて CSV に書き出す
python3 redmine_bulk_create.py --export 64,380 -p my-project --exclude-closed --out work/open.csv
```

### 行IDのルール

| 行IDの書き方 | 扱い |
|---|---|
| `S1`、`T1-2`、`デザイン` など | 新しく作る行(名前は自由。トラッカーとは関係しない) |
| `#453` | 既存のチケット #453 を更新する行 |
| `# 4月分の準備` など、`#` の後が数字だけでない | メモの行(読み飛ばす) |
| `453` など数字だけ、`-` だけ | エラー |

- 行IDは、同じファイルの中で、親として指定するための名前です。`S`・`W`・`T` などの頭文字に意味はなく、トラッカーは「トラッカー」の列だけで決まります。
- 同じファイルの中で重複させないでください。

### 空欄と「-」

| 書き方 | 新しく作る行 | 更新する行 |
|---|---|---|
| 値を書く | その値で作る | その値に変える |
| 空欄 | 既定値(担当者は自分) | 変更しない |
| `-` | なし(担当者なら「担当者なし」) | 空にする |

`-` で空にできるのは、担当者・開始日・期日・対象バージョン・カテゴリ・予定工数・説明・親です。

### 終了コード

| コード | 意味 |
|---|---|
| `0` | 正常に終わった(試し実行、反映の完了、確認で中止、書き出しの完了、反映するものがない) |
| `1` | 入力ファイルに問題がある、接続できない、プロジェクトやチケットが見つからない、など(何も反映していない) |
| `2` | 反映の途中で失敗した(それより前の行は反映済み)、または指定の誤り |

### 環境変数とファイル

| 名前 | 内容 |
|---|---|
| `REDMINE_API_KEY` | APIキー。設定されていれば、`~/.redmine_api_key` より優先する |
| `~/.redmine_api_key` | APIキーを書いたファイル(`chmod 600` にしておく) |
| `REDMINE_URL` | 接続先の既定値。`--url` を付けたときは、そちらが優先される |
| `logs/入力ファイル名-日時.csv` | 実行の記録(行ID・処理・チケット番号・題名・URL・注意)。`--apply` で反映したときに、入力ファイルの隣の `logs/` にできる |
